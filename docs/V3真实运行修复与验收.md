# V3 真实运行修复与验收

本版不将在线大模型连接标为演示。大模型问答实际调用配置的 Chat Completions HTTP 接口；配置缺失返回错误，不生成替代答复。DWSIM 通过本机 MCP 调用，故障不会自动换成参考结果。

## 本次发现并修复的问题

1. UI 新建任务默认参考回放，自定义任务还强制使用回放。现在 UI 和 API 默认均为 blind + dwsim，自定义任务遵循同一设置。新建页面不再提供参考模式选择。历史参考任务和显式调用的归档复核 API 保留其明确来源，不能自动变成真实求解；不删除用户历史数据。
2. 前端曾用 sanitizeSource 替换“归档、回放、Aspen”等来源文字。这会削弱可追溯性，已移除，原始来源完整呈现。
3. 连接成功后再遇到失败，旧成功提示可能残留。现在开始每次请求即清空上次状态，失败显示“最近请求失败”。成功标签指本次请求/测试成功，不承诺连接永久可用；刷新后重新显示配置状态。
4. 启动脚本只识别 RULE_ENGINE，可能误用其他目录/旧版本服务。现在核对目录标识和构建版本；发现不同实例明确停止，不自动终止其他任务。启动后轮询确认新服务就绪；CMD 在启动失败后不再提示打开旧地址。
5. 设备检查器曾固定显示 REPLAY_NOT_SOLVED。现在使用返回的 solver_status 与 converged，真实流股标为 SIMULATOR RESULT。

首页显示服务版本 `2026-10-10-v3`。如果仍看到“在线大模型连接为演示状态”，应核对使用的目录和运行版本；本次扫描的 V2/V3 源码和编译资源中没有找到该整句，无法断定用户当时看到它的具体来源。

## 已完成检查

- 179 项 pytest 通过，1 条既有 Starlette/httpx 弃用提示。
- TypeScript 与 Vite 构建通过。
- 浏览器实际验证：V3 版本显示、新建任务使用 DWSIM、空配置时报错；成功后失败会清除旧成功提示。成功分支使用浏览器测试替身，**不作为真实模型连接通过的证据**。
- PowerShell 语法通过；启动身份测试分别验证拒绝旧服务、拒绝其他目录、接受同目录同版本。身份测试使用隔离函数替身，没有启动或停止用户服务。
- API Key、base_url、model 继续为空；未购买服务或调用未授权外部模型。

- 真实模型供应商连接与多轮 Agent 任务：需要填入有效接口配置后实测。
- 当前机器真实 DWSIM 工艺计算：上一版执行遭 Windows Application Control 拦截；本次未绕过策略、未虚构求解。
- 真实工艺模板、标签映射和独立基准；仅有公开样本不能替代用户工艺。
- 任意自定义流程自动建模、自动参数优化和完整 TEA 仍未完成，自定义任务可能在流程建模阶段被明确阻止。
- 尚未微调大语言模型；本地已训练的是轻量检索排序器。

因此本包是“已接真实调用路径、完成局部与集成回归、待真实端到端验收”的代码，不能声称零缺陷或已具备生产交付可靠性。

## 启动核对

从本包所在目录按原流程运行 Setup-Offline.ps1，再 Start-ChemFlow.cmd。若旧服务占用默认端口，请从旧目录停止它，或用 `Start-ChemFlow.ps1 -Port 8766` 启动本版，然后访问该端口。首页应显示 `2026-10-10-v3`。

填 `config/llm.json` 后测试真实模型连接。DWSIM 使用 `config/dwsim.json` 与 Setup-DWSIM.ps1；遗留 `config/simulators.json` 不是当前 DWSIM 连接配置入口。
