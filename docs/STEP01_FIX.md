# Step 01 修复与验收

Step 01 现为设计基准核对页。新任务只自动读取对应 input.json，旧任务兼容迁移只补旧 Schema 缺少的字段、纠正输入来源类型；不覆盖用户的温度、纯度或其它修改。未读取 Ground Truth。

页面列出原料与反应、全部产品目标、副产物、工程约束、公用工程及可点击来源。VALIDATION_INPUT 与 USER_INPUT 区别明确。数值保留原始精度，PDH 进料温度原表为57.004380032573°C，概览按显示精度取整，未改写为57°C。

后端统一检查六项：组分、进料温度、压力、质量流量、反应、目标产品。返回 COMPLETE/MISSING/NEEDS_REVIEW 及详细缺失项。UI 使用同一校验接口显示6/6与按钮条件；流程解锁只依赖持久化 max_step/completed，不维护另一份锁定状态。人工确认不能绕过缺失字段。

底部始终显示保存和“确认并进入 Step 02”，不满足条件时列出原因。修复窄窗口按钮溢出。点击后保存当前 canonical ProjectSpec，确认第一步并进入第二步；刷新仍保留完成状态。

可选补充解析支持丙烷/丙烯/氢气及化学式、反应箭头、原料/目标/副产物意图、百分数纯度、塔顶压力上限。基于当前草稿合并，未知语句 NEEDS_REVIEW，不猜值，也不阻止已有完整基准继续。

验收：32项后端测试通过（含新增11项），两体系完整九步浏览器回归通过；新增 Step01 浏览器验收验证空自然语言、6/6、缺项阻断、确认后进入Step02、刷新保持、1280px/700px按钮可见。当前用户任务仅检查和兼容迁移，未代替用户勾选工程确认。
