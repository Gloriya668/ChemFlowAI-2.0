## 实际训练与验收结果

训练数据：60 条查询；开发集 8 条；测试集 12 条。按整个来源文件/流程组隔离；一份成本文档的所有分块也在同一分组。训练负样本只来自训练组。检索索引包含全部公开文档，这是检索任务的标准设置，测试查询和相关性标签没有进入梯度计算。测试组与训练组仍属于同一领域，不代表跨领域能力。

模型为 **4 特征线性成对排序器**，特征是 BM25、词项覆盖、标题覆盖、英文词覆盖；用成对 logistic loss 在 CPU 训练 300 轮、744 个正负样本对，开发集选择第 25 轮。模型权重是可审计 JSON，不依赖 torch、CUDA 或下载大模型。数据和权重哈希绑定；资料变化时自动退回 BM25，需重新训练。

| 12 条内部测试查询 | 首条命中 | 前三条命中 | MRR |
| --- | --- | --- | --- |
| 原 Agent 仅检索本地规则文件 | 0/12 | 0/12 | 0 |
| 扩充知识库 + 双语 BM25 | 10/12 | 12/12 | 0.9167 |
| 扩充知识库 + 已训练排序模型 | 10/12 | 12/12 | 0.9167 |

**训练排序器没有测得超出 BM25 的增益。** 原版没有外部流程案例，因此旧版 0 分主要反映覆盖不足，不能用来宣传“训练使性能从 0 提高到 100%”。数据与测试问句由规则生成或人工编写，尚未由化工专家独立标注；样本少，不能代表大赛真实评分、求解成功率、TEA 准确率或工程安全性。

`training/evaluation.json` 含逐条测试排名、开发集成绩、训练损失、模型权重与分组，失败项没有隐藏。知识库与 Agent 检索工具已经共用同一入口，引用附带原文件、URL、许可、STATIC_REFERENCE/RULE 标识。中文分词采用双字片段；对别名、缩写和超出资料范围的问题仍有限制。检索分数不是置信概率。未做神经向量检索或外部重排服务。

## 使用和重训

1. 按原方法安装并启动 ChemFlow，进入项目里的“工程 Agent 任务”。展开“工程知识库”，可直接中文检索，不需要填 API。
2. 填写 `config/llm.json` 后，Agent 的 `search_knowledge` 工具自动使用新知识库。没有 API 时，不能实际运行大模型多轮任务。
3. 执行 `./Train-Knowledge.ps1 -PythonExe "你的python.exe"` 重建语料并训练。Python 3.12 标准库即可；脚本会覆写本版的派生语料、权重和评估记录，保留原始来源。
4. 全量测试：在项目目录运行 `python -m pytest -q`。新增数据来源校验、训练测试隔离、检索/API/Agent 接入、模型失效回退等测试。
5. `GET /api/knowledge/status` 查看实际加载模型；`GET /api/knowledge/search?q=天然气处理` 检索。

## 大赛前仍需补齐的关键项

- 真实 DWSIM 执行：上一版在本机遭 Windows Application Control 拦截；本次未绕过策略，也未声称产生真实求解。必须解决可信运行部署并注册真实工程模板。
- 经专家确认的工程基准集：含不同工况、失败案例、质量/能量闭合、物性适用性和独立实测/文献值。归档值不能当作独立真值。
- 真实任务轨迹：记录需求澄清→工具参数→求解→诊断→修复→核验，划分流程家族留出集，而非只增加相似问句数量。
- 完整经济评估：收集有日期、币种、基年及来源的设备关联、价格、开工率和现金流。IDAES 源码进库不等于已接入其成本求解器，也不等于生成可靠 CAPEX/NPV/IRR。
- 自动优化与流程建模：仍需约束、目标、优化器及失败恢复。当前知识检索训练没有补齐这些数值能力。

这些是工程数据和数值验证工作，不能通过继续堆积文本样本自动替代。
